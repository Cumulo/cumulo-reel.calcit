# 类型边界下游回归：草稿交付复核

对应 Respo 0.19.0 milestone 的 #194，使用 Respo 类型边界分支完成真实 demo 回归。当前交付保持草稿，尚未满足完整发布依赖与严格客户端验收。

## 当前源码与验证

Respo 本地覆盖已从此前的 `7644b19` 更新至 `f03961e`。Recollect、ws-edn 等仍为本地迁移覆盖，未修改共享缓存或生成文件入库。

| 验证 | 本轮结果 |
| --- | --- |
| 正式 Calcit 0.28 原生附属测试 | 24/24 |
| 候选 Calcit alpha.1 原生附属测试 | 24/24 |
| 正式服务端严格检查 | 通过 |
| 正式客户端严格检查 | 失败：两条已绑定 nullable watcher 的参数类型告警 |
| 候选客户端严格检查 | 通过 |
| 正式新生成服务端 JS，共享协议测试 AST 回放 | 16 项协议断言通过 |
| Node 服务端运行测试 | 4/4，包括共享协议、WebSocket 重连、绑定错误退出、临时持久化 |
| 候选新生成客户端 JS + Node 24 Vite 构建 | 通过 |
| 原质量基线 | 失败：77 项逐定义回归，未放宽预算 |

协议边界从原始 EDN 校验 patch 与完整 ClientStore，保留合法 nil/开放路由数据。错误批次、嵌套字段或操作参数不会发布部分状态。共享 native/JS 测试覆盖初始快照、增量更新、错误参数与原子拒绝；此前的真实浏览器测试记录见 README 和 `docs/realtime-reel.md`。

客户端与服务端 JS 分别输出到 `js-out`、`js-server-out`，避免构建相互覆盖。草稿 PR 只执行验证，COS 预览上传留到非草稿阶段。

## 剩余交付条件

正式客户端两条 watcher 告警需要已验证的编译器修复发布；不能通过丢失 callback 泛型、恢复 Dynamic 或修改运行行为绕过。依赖清单尚未固定全部已发布迁移模块，因此本地覆盖成功不能证明 `caps` 从发布版本重建成功。质量门禁与实际依赖版本应一起收敛后，再将草稿转为正式审阅。
